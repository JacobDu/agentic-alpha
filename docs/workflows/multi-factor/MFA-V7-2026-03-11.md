# MFA-V7 Rank-Buffer Exit Research

> **Date**: 2026-03-11
> **Round ID**: MFA-V7-2026-03-11
> **Market**: CSI1000 (SH000852)
> **OOS**: 2025-01-01 ~ 2026-03-10
> **Data Release**: 2026-03-11
> **Note**: 2026 is truncated in-year OOS.

## 1. Goal

Test a V7 strategy variant that replaces `TopkDropoutStrategy`'s minimum holding-day gate with a rank-buffer trigger:

- if any current holding drops below `rank m`
- remove the lowest-ranked `x` holdings
- buy top-ranked non-held names to refill to `topk=20`

The purpose is to check whether a rank-buffered exit translates 1d ranking signals more effectively than the current `hold_thresh=80` design.

## 2. Setup

### 2.1 Model and data

| Dimension | Config |
|------|------|
| Model | Ensemble (XGBoost + LightGBM mean) |
| Training | Rolling 3m retrain, 5 windows |
| Train start | 2018-01-01 |
| Features | Alpha158 + DB factor Top30 (max_per_cat=5) |
| Label | 1d forward return |
| Cost | open=5bp, close=15bp, min_cost=5 |

### 2.2 Strategies compared

Baseline:

- `TopkDropout(topk=20, n_drop=2, hold_thresh=80)`

V7 candidates:

- `buffer_rank ∈ {40, 60, 80, 100}`
- `n_drop ∈ {1, 2, 3}`
- trigger: if any holding rank exceeds `buffer_rank`, sell the bottom `n_drop` holdings

### 3.2 Key findings

1. The best V7 candidate (`drop=2`) materially outperformed the current V6 baseline on the updated OOS:
   - IR: `0.855 -> 1.785`
   - annualized excess return: `+12.53% -> +22.50%`
   - max drawdown: `-17.12% -> -9.29%`
2. `buffer_rank` had almost no effect for `40~100`. All `drop=2` runs produced identical metrics.
3. The true driver in this scan was `n_drop`, not `buffer_rank`:
   - `drop=2` was best
   - `drop=1` was too conservative
   - `drop=3` improved raw return but paid too much turnover
4. Turnover is the main trade-off:
   - baseline: `1.60%`
   - V7 best: `17.43%`

### 3.3 Follow-up: TopkDropout `hold_thresh` sweep on the same OOS

To test whether the V7 gain was really from a new "buffer" mechanism, I reran the same model/predictions with plain `TopkDropout(topk=20, n_drop=2)` and only changed `hold_thresh`.

| Rank | Strategy | hold | Effective cycle | Ann. Excess (w/c) | IR (w/c) | MaxDD | Daily Turnover |
|---|---|---:|---:|---:|---:|---:|---:|
| 1 | TopkDropout | 60 | 600d | +40.21% | +2.192 | -14.24% | 2.10% |
| 2 | TopkDropout | 80 | 800d | +32.15% | +1.792 | -11.69% | 1.51% |
| 3 | TopkDropout | 1 | 10d | +22.59% | +1.792 | -9.28% | 17.45% |
| 4 | TopkDropout | 5 | 50d | +30.86% | +1.676 | -10.34% | 9.12% |
| 5 | TopkDropout | 20 | 200d | +15.31% | +0.855 | -16.77% | 4.52% |
| 6 | TopkDropout | 10 | 100d | -3.27% | -0.250 | -19.08% | 6.28% |
| 7 | TopkDropout | 40 | 400d | -5.31% | -0.397 | -26.93% | 2.65% |

**Key implications**

1. `hold_thresh` is clearly **non-monotonic** on this updated OOS. It is not true that "the longer the hold, the worse the return."
2. The best point in this scan is `hold=60`, not `hold=1`.
3. `hold=1` is strong, but not because it dominates all longer holds. It mainly acts as a high-turnover, high-cost version of the strategy.
4. `hold=40` and `hold=10` both failed on this OOS, so the relationship is not even "shorter is always better" or "longer is always better" - there is a regime effect.
5. The earlier V7 best run is almost numerically identical to `TopkDropout hold=1`:
   - V7 `buf40_drop2`: ann. excess `+22.50%`, IR `1.785`, MaxDD `-9.29%`, turnover `17.43%`
   - TopkDropout `h1`: ann. excess `+22.59%`, IR `1.792`, MaxDD `-9.28%`, turnover `17.45%`

This means the current V7 formulation did **not** discover a new buffer effect. It mostly collapsed into a de facto `hold_thresh=1` strategy.

## 4. Interpretation

This first V7 scan shows that a more aggressive exit rule can unlock much better signal translation on the 2025-01-01 to 2026-03-10 OOS.

However, the current implementation does **not** prove that "rank buffer" itself is the key mechanism, because:

1. `buffer_rank=40/60/80/100` is effectively non-binding in this formulation.
2. The strategy behaves much closer to "sell bottom `x` frequently once any breach exists" than to a tightly controlled hysteresis rule.
3. Follow-up hold-sweep evidence shows the current V7 best is essentially equivalent to plain `TopkDropout hold=1`, so the observed gain came from loosening the hold gate, not from buffer logic itself.

So the evidence supports **the direction**, but not yet the exact V7 rule design.

## 5. Decision

**Iterate**

Reason:

- The result is strong enough to justify continuing V7 research.
- But the current formulation is under-identified: `buffer_rank` did not separate candidates, so this is not yet a clean Promote-quality strategy definition.

## 6. Next Actions

1. Compare directly against `TopkDropout` with low-hold variants on the same updated OOS:
   - `hold_thresh ∈ {1, 5, 10, 20}`
2. Compare the next V7 candidates against the new best plain baseline:
   - `TopkDropout(topk=20, n_drop=2, hold=60)`
3. Tighten the buffer search to the regime where it may actually bind:
   - `buffer_rank ∈ {20, 25, 30, 35}`
4. Test a stricter exit formulation:
   - sell only names that are themselves outside `buffer_rank`
   - versus current "if breached, sell bottom x overall"
5. Test hybrid designs:
   - small `min_hold` + rank buffer
   - e.g. `min_hold=5` with `buffer_rank=30/40`
